# Task 005: Add structured logs/metrics for return shapes

## Description

Implement JSON-structured logging to track RAG call results and detect edge cases. This will provide visibility into RAG operation patterns and help identify issues before they cause failures.

## Phase

2

## Acceptance Criteria

- [ ] JSON-structured logging implemented for RAG operations
- [ ] Log output directed to /tmp/rag_test.log
- [ ] Log entries include all required fields: provider, query_length, status, doc_count, error_type, has_answer
- [ ] Analysis script created at /tmp/analyze_logs.sh
- [ ] Logging captures both successful and failed RAG operations
- [ ] Log format is parseable and queryable
- [ ] Performance impact of logging is minimal

## Technical Details

The structured logging implementation should:
- Use JSON format for structured data capture
- Log each RAG operation with standardized fields:
  - provider: Which AI provider was used (OpenAI, Gemini, etc.)
  - query_length: Character count of the input query
  - status: success/error/timeout
  - doc_count: Number of documents retrieved
  - error_type: Classification of error if operation failed
  - has_answer: Boolean indicating if a meaningful answer was generated
- Output logs to /tmp/rag_test.log for analysis
- Include timestamp and operation ID for correlation
- Provide log rotation to prevent disk space issues

## Dependencies

- Current RAG operation implementations
- Python logging framework
- JSON serialization capabilities
